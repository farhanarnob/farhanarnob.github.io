Research

Large software projects receive thousands of bug reports, and someone has to decide who should fix each one. When that call is wrong, the report gets passed from developer to developer and the fix waits. My dissertation builds models that make this routing decision from the report text, the project's records about components and teams, and its commit history. I test them the way they would be used in practice: trained on the past and evaluated on reports that come later.

  1. 2025

    Commit messages as a signal

    Adding developers' commit messages to an XLNet model raised Top-1 accuracy on Firefox from 23.28% to 69.45%, and on Eclipse from 47.89% to 84.88%.

  2. 2026

    A model a project could deploy

    A hybrid transformer combining report text with project metadata reached 69.02% Top-1 and 90.69% Top-10 accuracy on 25,220 Firefox reports. Text and metadata alone reach 99.6% of the full model, so it still works when no commit history exists yet.

  3. 2026

    Learning how reports really move

    A learning-to-rank framework (LightGBM LambdaMART) with an implicit routing graph, evaluated in strict chronological order on Firefox, Chromium and Eclipse. It reached 75.5%, 47.7% and 65.4% Top-1 accuracy against 42.0%, 22.9% and 43.1% for a tossing-graph baseline. Under review.

  4. Next

    Routing that keeps up with real teams

    Handling newcomers with little history, changing teams, developer workload and signals from the code itself.

Other interests: mining software repositories, mobile and context-aware systems, and software testing. In the lab I also extended and rebuilt our mobile app and server for collecting smartphone context data. My experiments run on the Lonestar6 supercomputer at the Texas Advanced Computing Center through an NSF ACCESS allocation awarded to Dr. Bryce; I prepared the proposal and am its sole research user.
